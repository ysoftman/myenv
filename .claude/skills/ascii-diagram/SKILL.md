# ASCII Diagram

응답 텍스트(또는 마크다운 문서) 안에 코드펜스로 감싼 박스 드로잉 다이어그램을 그린다.
파일을 만들지 않는 것이 기본 — 사용자가 문서로 남기라고 하면 마크다운에 같은 블록을 넣는다.

## 기본 규칙

- 코드펜스로 감싼다. 언어 태그는 `text` 만 쓴다 — 하이라이트가 붙으면 선이 깨지고,
  태그를 아예 빼면 마크다운 문서로 저장할 때 lint(MD040)에 걸린다.
- 폭은 **100칸 이내**. 넘으면 세로로 쌓거나 다이어그램을 2개로 나눈다.
- 문자셋: `─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼` (박스), `═ ║ ╔ ╗ ╚ ╝` (경계·강조), `▶ ◀ ▼ ▲` (화살표 머리).
- **이모지 금지.** 폭이 환경마다 달라 정렬이 깨진다. 상태 표시는 `(활성)`, `[Ready]`, `*` 로 한다.
- **한글은 폭 2칸**으로 계산해 박스 안쪽을 맞춘다. 한글이 섞인 줄은 눈으로 맞추지 말고 아래 검증을 돌린다.
- 화살표에는 항상 라벨을 붙인다 (`──── 미러링 ────▶`, `│ topic: events`). 라벨 없는 선은 정보가 없다.
- 박스 안은 **제목 + 핵심 2~4줄**까지. 그 이상 수치·설정은 다이어그램 아래 표로 뺀다.

## 패턴

### 1. 파이프라인 (좌→우 또는 위→아래)

단계가 순차적일 때. 단계 사이에 무엇이 흐르는지 라벨로 적는다.

```text
  ┌────────────┐ 로그 파일  ┌────────────┐  topic: x  ┌────────────┐  bulk API  ┌────────────┐
  │ collector  │───────────▶│   kafka    │───────────▶│  logstash  │───────────▶│ opensearch │
  └────────────┘            └────────────┘            └────────────┘            └────────────┘
```

### 2. 좌우 비교 / 이전(migration)

기존 환경과 신규 환경을 `═` 세로 경계로 나눈다. 공통 진입점은 경계 위에 둔다.

```text
                             공통 진입점 (VIP / DNS)
                                        │
  ═════════════════════════════════════ │ ══════════════════════════════════
    기존 (PM)                           │      신규 (k8s)
  ═════════════════════════════════════ │ ══════════════════════════════════
    ┌───────────────┐                   │      ┌────────────────┐
    │ 컴포넌트 A    │──── 미러링 ───────┼─────▶│ 컴포넌트 A'    │
    └───────────────┘                   │      └────────────────┘
```

### 3. 계층 / 포함 (네임스페이스·클러스터 경계)

바깥 박스 안에 안쪽 박스를 넣는다. 2단계까지만 — 3단계부터는 다이어그램을 분리한다.

```text
  ┌─ ns: messaging ──────────────────────────┐
  │   ┌───────────┐   ┌───────────┐          │
  │   │ broker 0~2│   │ ctrl 100~2│          │
  │   └───────────┘   └───────────┘          │
  └──────────────────────────────────────────┘
```

### 4. 단계/타임라인 (컷오버 절차)

번호 + 화살표. 되돌릴 수 있는 지점(롤백 포인트)을 표시한다.

```text
  (1) LB 생성 ──▶ (2) 광고 주소 반영 ──▶ (3) 멤버 교체 ──▶ (4) 미러링 중단
                                        ▲ 롤백 지점(멤버 되돌리기)
```

## 조합 규칙

- 다이어그램 하나에 패턴 하나. 아키텍처 + 모니터링 + 절차는 **각각 별도 블록**으로 그린다.
- 다이어그램 아래에 상태 요약 표를 붙인다 (컴포넌트 × 환경 × 상태). 다이어그램은 관계, 표는 수치.
- 다이어그램 안에 담기 애매한 단서(주의사항, 남은 작업)는 블록 밖 `※` 줄이나 본문 문장으로.

## 조립과 검증 — `scripts/draw.py`

**손으로 컬럼을 세지 말 것.** 한글 2칸 + 박스 문자 1칸이 섞이면 눈으로 못 맞추고,
매번 조립 코드를 새로 짜면 시행착오만 반복된다. 헬퍼를 import 해서 쓴다.

`scripts/draw.py` 를 **먼저 읽고**(함수 목록과 사용법이 그 파일 docstring 에 있다) import 해서 쓴다.
`box` `merge` `cross` `flow` `place` `at` `ctr` 로 조립하고, 컬럼은 절대값으로만 넘긴다 —
`at()` 을 문자열 덧셈으로 이어붙이면 직전 컬럼을 빼야 하고, 그 -1 을 빼먹어 `▼` 가 1칸 밀린다.

조립 스크립트는 결과를 stdout 으로 print 하고, 스크래치 디렉토리의 파일로 저장한 뒤 검증한다.
블록이 여러 개면 각각 저장했다가 제목을 붙여 하나로 모은다 (클립보드 복사용).

```bash
python3 build.py > diagram.txt                      # 조립 스크립트의 출력을 저장
python3 <스킬경로>/scripts/draw.py < diagram.txt    # 줄별 폭 + 세로 컬럼, 폭 초과·밀림은 !!
python3 <스킬경로>/scripts/draw.py demo             # 헬퍼 자체 동작 확인 (선택)
```

폭이 어긋나면 박스 오른쪽 변(`│`)을 맞추기보다 **오른쪽 변을 생략**하는 편이 빠르다 —
왼쪽 정렬만 맞으면 읽는 데 지장이 없다 (`┌ 제목` / `│ 내용` / `└ 내용` 형태).

## 클립보드 복사 (항상)

응답에 다이어그램을 보여준 뒤, 사용자가 다른 곳에 붙여넣을 수 있도록 **매번** 클립보드에
복사한다. 블록이 여러 개면 제목을 붙여 한 번에 담는다.

```bash
# macOS / Linux / WSL 순으로 있는 것을 쓴다
cat diagram.txt | (pbcopy 2>/dev/null || xclip -sel clip 2>/dev/null || clip.exe)
```
